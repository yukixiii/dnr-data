# データ抽出ガイド (ドラフト作成用)

ドラゴンネストR(日本版)の装備データベース用に、`ingest/raw/*.txt` (公式お知らせ等を `ingest/fetch-notices.ts` でテキスト化したもの) から構造化データを抜き出し、ドラフトJSONを作る手順。

## 出力
- `ingest/drafts/<担当名>.json` に `src/types.ts` の `Dataset` 形式 (`sources, items, materials, recipes, enhance_tables, drops, dungeons` の各配列) で書く。
- 書いたら `npx tsx ingest/validate.ts ingest/drafts/<担当名>.json` を実行し、`OK` になるまで直す。
- `src/types.ts` と `data/schema/dnr.schema.json` が型定義。フィールドの意味は types.ts のコメントを読むこと。
- 他のファイルは編集しない。

## 抽出対象 (装備の作成ルート・ステータス・強化率・ドロップ率に関係するもの)
- 装備 (武器/防具/アクセサリー/特殊防具)、アーティファクト、タリスマン、竜珠、紋章: 名称、部位、等級、レベル、系統、最大強化値、ステータス(段階別があれば StatSet を分ける)
- 作成/進化/増幅/精製/交換レシピ: 結果、前段装備(base)、素材と個数、ゴールド、NPC/商店、成功率
- 強化・製作段階・精製などの確率表 (段階ごとの確率、費用、素材、失敗時の挙動)
- ダンジョン/ネスト/ステージ/採集/クリア報酬/箱の中身のドロップ表 (確率が数値なら rate、"確定""一定確率""低確率"等は rate_text)
- 上記に関わる素材・通貨・箱 (materials に入れる)、ダンジョン (dungeons に入れる。入場条件・レベル・難易度も)

## 対象外
クラス・スキル調整、アバター/コスチューム、純粋なキャッシュショップ販売情報(ただし装備・素材関連の箱の提供確率表は対象)、イベント日程、称号、不具合修正、次元レベル等の装備に無関係なシステム。迷ったら装備強化・作成に関係するかで判断。

## ルール
- **数値をでっち上げない。** 原文にない数値・素材は書かない。不明な点は `notes` に書く。
- **アイテム/ダンジョンの id は原文の日本語名称そのもの** (全角/半角・記号も原文どおり)。`name` も同じ値。複数ドラフトを id で突き合わせて統合するため、表記ゆれに注意 (同じ物が別表記なら原文で多い方に統一し notes に別表記を記載)。
- 参照するアイテム・ダンジョンはすべてそのドラフト内で定義する (情報が少なくても `id, name, kind, refs` だけのスタブで良い)。
- recipe / enhance_table / drop の id は `n<お知らせ番号>-<短い英数字>` (例: `n1440-belscard-resp-enhance`)。
- 出典: お知らせ1件ごとに source を1件。`id: "jp-notice-<no>"`, `url` (txt の2行目), `region: "JP"`, `kind: "official"`, `title` (txt の1行目), `published_at` (本文の「作成日」の日付), `fetched_at: "2026-10-04"`。全レコードの `refs` にその source を入れる。
- 表は `[TABLE]...[/TABLE]` にタブ区切りで平坦化されている。**rowspan のせいで、セル数が少ない行は前の行の先頭セルを引き継いでいる**ことが多い。列見出しと照らし合わせて慎重に解釈する。画像のみの表は空 `[TABLE][/TABLE]` になっている (中身は取れないので notes に「画像のため未取得」等)。
- 「(更新)」で後から修正された記述がある場合は修正後の値を採用し、notes に修正履歴を残す。
- 新しいお知らせが古い内容を変更している場合 (例: 最大強化値の拡張、確率変更) は、その変更内容をそのお知らせの出典で記録し notes に「◯年◯月アップデートで変更」と書く。
- 確率 rate は % の数値 (例: 3.00% → 3)。
- stats の value は原文表記の文字列 (例: "260,000", "17.00%")。
- 段階・等級・増幅違いの装備 (`[3段階]X`, `X(レア)`, `[増幅]X` 等) は原文の名称どおり別アイテムとして登録する。1装備へのまとめは統合後に `data/item_groups.json` で行う (README 参照)。

## 最後に返す報告 (短く)
- 扱った装備系統・主要アイテム、作ったレコード件数
- 画像のみで取れなかった重要情報、解釈に迷った箇所、他時期のお知らせとの矛盾の可能性
